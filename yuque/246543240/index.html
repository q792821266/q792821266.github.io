WebSocket

是什么

WebSocket是一种协议。定义了如何在一个已经建立的TCP连接上进行全双工同行，包括握手、数据帧格式、关闭连接的规则等

  • WebSocket有明确的RFC标准（RFC 6455），规定：

  • 握手过程（基于HTTP Upgrade）

  • 数据帧格式（文本帧、二进制帧、控制帧）

  • 心跳、关闭连接的机制

  • 运行在TCP上，是应用层协议

为什么需要WebSocket

  • HTTP的局限性

  • HTTP是请求-响应模型，客户端必须主动发起请求，服务端不能主动推送

  • 如果需要实时数据（如聊天、股票行情、游戏），只能用轮询或长轮询，效率低、延迟高

  • WebSocket的优势

  • 全双工通信：客户端和服务端可以相互主动发送消息

  • 单连接长时间保持：减少频繁握手开销

  • 低延迟：适合实时应用

长轮询

HTTP长轮询（Long Polling） 是一种在HTTP请求-响应模型下模拟“实时推送”的技术，主要用于在没有WebSocket的情况下实现服务器向客户端的“近实时”消息传递

普通轮询：客户端定时发送请求（比如每秒一次），浪费带宽

长轮询：客户端发起请求后，服务端保持连接，直到有数据才返回，减少无效请求

工作原理

  • 客户端发起请求

  • 客户端向服务器发送一个普通的HTTP请求，但是服务端不会立即返回响应

  • 服务端保持连接

  • 如果没有新数据，服务器会挂起这个请求，知道有数据或超时

  • 有数据时立刻响应

  • 一旦服务器有新消息，就立即返回响应给客户端

  • 客户端再次发起请求

  • 客户端收到响应后，立即重新发起新的请求，保持“长轮询”循环

特点

  • 比普通轮询更高效，减少空请求
  • 兼容所有浏览器和HTTP基础设施

缺点

  • 每次响应后人需要重新建立HTTP请求，握手开销仍在
  • 不是真正的双向通讯，延迟比WebSocket高
  • 对服务器压力大（大量挂起请求）

为什么服务端不即时响应

  • 如果服务端立刻响应（即使没有新数据）那就变成了普通轮询，客户端会频繁发起请求，浪费带宽和资源
  • 长轮询的设计是：客户端发起请求后，服务端故意挂起请求，直达有新的数据或超时才返回，这样可以减少无效请求

服务端为什么能挂起请求

  • HTTP是基于TCP的，连接可以保持一段时间
  • 服务端通过异步I/O或者线程阻塞，等待事件发生，比如新消息到达
  • 一旦有数据，立刻响应，客户端再发起新请求，形成“伪实时”效果

挂起请求时故意的，目的是为了：

  • 降低频繁轮询的开销
  • 模拟服务器主动推送
  • 如果超时（比如30秒），服务器返回空响应，客户端重新发起请求

在 HTTP/1.0 中，确实是“一次请求对应一次连接”，响应完成后连接关闭 , 不支持 keep-alive 导致频繁断开重连，性能更差

在** HTTP/1.1 **下，长轮询可以利用 keep-alive，避免每次都重新建立 TCP 连接

HTTP vs WebSocket 区别

特性 HTTP WebSocket
通信模式 请求-响应 全双工（双向）
连接方式 短连接（默认） 长连接
数据格式 文本（HTTP Header） 二进制或文本
服务器推送 不支持 支持
应用场景 普通网页请求 聊天、推送、游戏

WebSocket的原理

  • 握手阶段

  • 基于HTTP协议发起请求，使用Upgrade：websocket头

  • 服务器响应101 Switching Protocols ， 协议升级完成

  • 通信阶段

  • 使用TCP长连接，数据以帧（Frame）形式传递

  • 支持文本和二进制，且是全双工

协议升级

为社么通过HTTP协议升级，或不设计新的协议

  • 兼容现有基础设施

  • WebSocket握手使用标准HTTP请求（带Upgread: websocket头）

  • 防火墙和代理兼容性： 企业网络通常只允许 HTTP/HTTPS 流量，直接新协议很可能被拦截

  • 复用已有的认证和安全机制

  • 认证和安全机制： HTTP 已经有成熟的认证（Cookie、Header）、加密（TLS）体系，WebSocket 可以直接复用。

  • 负载均衡和代理支持：HTTP Upgrade 握手可以穿过现有的代理和负载均衡设备，而新协议需要重新适配

  • 渐进式升级

  • 如果服务器不支持 WebSocket，可以回退到 HTTP 长轮询，保证兼容性

  • 如果直接设计新协议，所有浏览器、服务器、代理都要重新实现，成本极高

关键

  • WebSocket 是应用层协议，基于 TCP 长连接。
  • 它通过 HTTP Upgrade 完成握手，但之后不再使用 HTTP 语义。
  • 所以不能说它是 HTTP 的“升级版”，而是一个独立协议，借助 HTTP 建立连接
  • ** WebSocket 的握手依赖 HTTP，但通信完全是 WebSocket 协议在 TCP 上运行，与 HTTP 无关 **
