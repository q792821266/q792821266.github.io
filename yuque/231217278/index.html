Spring的响应式编程

Spring的响应式编程时基于Reactive Streams规范的一种编程范式，旨在处理异步数据流，特别适合于高并发、IO密集型的应用场景。它的核心目标是提高系统的 可伸缩性 和 资源利用率，尤其是在微服务架构中非常有价值。

🌟 核心概念

  1. Reactive Programming （响应式编程）
  • 是一种声明式编程范式，强调数据流和变化传播
  • 使用异步、非阻塞的方式处理数据流，避免线程阻塞
  1. Reactive Streams 规范
  • 包括四个核心接口：Publisher ，Subscriber，Subscription，Processsor
  • 解决了背压（Backpressure）问题，即消费者处理不过来时，生产者可以减缓数据推送速度
  1. Project Reactor

  • Spring响应式编程的基础库，提供两个核心类型

  • Mono<T>：表示0或1个元素的异步序列

  • Flux<T>：表示0到N个元素的异步序列

⚙️ Spring WebFlux

Spring WebFlux 是 Spring 提供的响应式Web框架，支持

  • 非阻塞式编程模型
  • 基于Reactor的响应式流处理
  • 支持注解式编码（类似Spring MVC）和函数式编程风格

✅ 优势

  • 高并发性能好，适合处理大量并发请求
  • 更少的资源消耗（线程、内存）
  • 更适合微服务架构中的异步通信

⚠️ 注意事项

  • 编程模型复杂度高，调试困难
  • 与传统阻塞式库（如JDBC）不兼容，需使用响应式库（如R2DBC）
  • 不适合所有场景，尤其是CPU密集型任务

🧠 传统阻塞式 vs 响应式编程的本质区别

特性 传统 Spring MVC Spring WebFlux
编程模型 阻塞式 非阻塞式、异步
返回值 直接返回对象（如 String
, Model
, ResponseEntity

🔄 为什么使用 Mono 和 Flux

  1. 异步数据容器
  • Mono<T>表示异步计算结果（最多一个值）
  • Flux<T>表示异步数据流（多个值）
  • 它们不是数据本身，而是对数据的”承诺“或”流“
  1. 延迟执行（Lazy Evaluation）
  • 数据不会立即计算，而是在订阅（subscribe）时才会执行
  • 这让你可以组合、替换、过滤数据流，而不会立即触发计算
  1. 非阻塞处理
  • 当你返回Mono<String>，你是在告诉框架：我会在未来的某个时间点提供一个字符串
  • 框架可以继续处理其他请求，而不是等待这个字符串准备好
  1. 统一响应式管道
  • 所有处理逻辑（数据库、服务调用、IO）都可以用Mono/Flux组合起来，形成一个响应式链条

📦 类比理解：Mono/Flux 就像快递单

  • Mono<String> 就像你下单后拿到的快递单号，它不是快递本身，但你知道快递会送来。
  • Flux<String> 就像你订阅了一个杂志，每期都会送来一本，但你不知道具体什么时候。
