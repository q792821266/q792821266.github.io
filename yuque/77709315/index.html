类加载机制

对于类加载的机制，之前我们应该也有一定的了解。我们知道运行时数据区，一个JVM要去执行java代码、实现业务逻辑 ，那么只能通过class文件来读取。于是我们应该考虑JVM是如何加载java代码的？我们虽然知道字节码被加载之后会对放到对应的方法区、堆内存，是谁负载加载这个class文件呢？这个class文件在我们的磁盘，在jar，在某个位置。

要了解这个加载的过程，需要从类的生命周期开始讲起。

类生命周期

  1. 加载 读取二进制内容
  2. 验证 验证class文件格式规范、语义分析、引用验证、字节码验证，防止串改了服务器代码
  3. 准备 分配内存，设置类static修饰的变量初始值
  4. 解析 类、接口、字段、类方法等解析
  5. 初始化 为静态变量复制，执行静态代码块
  6. 使用 创建实例对象
  7. 卸载 从JVM中卸载对象

后面过程我们只需要关注前面5个步骤就可以了。

类加载器

类加载器负载装入类，搜索网络、jar、zip、文件夹、二进制数据、内存等指定位置的类资源。一个java程序运行，最少有三个类加载器实例，负责不同类的加载，为什么是三个这个只是职责的问题。

  1. Bootstrap Loader c/c++实现，无对应java类，加载JRE_HOME/jre/lib目录或者永无配置目录。专门加载核心类库（Object），java虚拟机最终还是有c来实现的，现有c后有java。
  2. Extension Class Loader 加载JRE_HOME/jre/lib/ext目录，JDK拓展包。加载扩展类目，每个平台需要的可能不一样，非必须的依赖
  3. application class loader 加载java.class.path指定的目录，这个就是加载我们开发人员所写的代码。它通过java.class.path来知道应用程序的入口
