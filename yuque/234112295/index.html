📦 第三方库兼容性变化

  • 所有使用 javax.* 的库必须升级到支持 jakarta.* 的版本。
  • Spring Data、Spring Cloud、Hibernate、Elasticsearch 等都需要升级到兼容版本。
  • 例如：Spring Data JPA 要升级到 2022.x 或更高版本****。

✅ 升级建议

  1. 不要直接从 2.0 升级到 3.0，建议先升级到 2.7，再迁移到 3.0****。
  2. 确保测试覆盖率，包括单元测试、集成测试和回归测试。
  3. 使用迁移工具：如 Spring Boot Migrator、OpenRewrite、IDEA 的 Jakarta EE 批量替换功能。

自动装配机制的变更

Spring Boot 3.0对自动装配机制进行了重要变更，主要是废弃了传统的 spring.factories 文件方式，改用新的AutoConfiguration.imports 文件机制。

🧩 Spring Boot 自动装配机制变更详解（2.0 → 3.0）

✅ 旧机制（Spring Boot 2.x）

  • 自动配置类通过 @EnableAutoConfiguration 注解启用
  • 自动配置类在 META-INF/spring.factories 文件中注册，格式如下：
  • Spring Boot 会扫描 spring.factories 文件并加载对应的配置类

🔄 新机制（Spring Boot 3.x）

  • 自动配置类的使用新的注解@AutoConfiguration (它是@Configuration的元注解)
  • 自动配置必须在 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports文件中注册
  • 每行一个类名，支持注释（以#开头）
  • Spring Boot不再支持通过spring.factories 注册EnableAutoConfiguration， 该方式已被移除

📌 为什么要变更？

  • 性能优化：新的机制更轻量，启动更快。
  • 更清晰的结构：将自动配置与其他 Spring Boot 扩展机制分离。
  • 更强的类型安全：通过 @AutoConfiguration 明确标识自动配置类。
  • 更好地支持 GraalVM 原生镜像：旧机制依赖反射，不利于 AOT 编译。

⚠️ 注意事项

  • 如果你维护的是第三方库或公司内部 starter，需要：

  • 添加 AutoConfiguration.imports 文件。

  • 使用 @AutoConfiguration 注解替代 @Configuration。

  • 不再依赖 spring.factories 注册自动配置类****。

  • Spring Boot 2.7 是过渡版本，支持两种方式，但会发出警告。

原理

Spring Boot 3.x 的自动装配机制不再依赖反射来发现和加载自动配置类。这是为了更好地支持AOT（Ahead-of-TIme）编译和GraalVM原生镜像

编译时收集配置类

  • Spring Boot 在构建过程中（使用 Maven/Gradle 插件）会扫描所有带有 @AutoConfiguration 的类。
  • 这些类的全限定名被写入 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports 文件。
  • 这个文件在运行时被 Spring Boot 读取，直接加载类，而不是通过反射查找

AOT 支持

  • Spring Boot 3 引入了 spring-aot 模块，用于在构建阶段生成优化后的代码。
  • 自动配置类在 AOT 编译时被提前处理，生成静态代码，避免运行时反射。
  • 这使得应用可以更快启动，并能编译为 GraalVM 原生镜像。

条件注解仍然有效

  • 自动配置类仍然可以使用 @ConditionalOnClass、@ConditionalOnMissingBean 等注解。
  • Spring Boot 在 AOT 编译时会分析这些条件，并生成相应的判断逻辑。
