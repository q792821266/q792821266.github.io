加入Hexo

太好了，这一步是把你这个 Agent 项目真正“落到 Hexo 级别”的关键一步。
我会 完全按你现在真实在用的 Hexo + GitHub Pages 场景，给你一套 “Hexo 专用 Skill 设计”，而不是泛泛而谈。

目标非常明确：

✅ Agent 懂 Hexo 目录与规则
✅ Agent 安全地生成 / 更新文章
✅ Agent 自动 build / deploy Hexo
✅ Agent 不破坏你已有的 Hexo 工作流

下面内容你可以直接照着建目录、写代码。

✅ 一、Hexo + Agent 的正确协作模型

先明确一个非常重要的定位：

Agent 不“理解 Hexo”
Skill 才“懂 Hexo”

Agent 只会做这种决定：

  • “我要新增一篇文章”
  • “我要优化这篇 post”
  • “可以发布了”

所有 Hexo 细节（路径 / CLI / 配置）都必须藏在 Skill 里。

✅ 二、Hexo 专用 Skill 总览（最小但完整）

我建议你 只做 4 个 Hexo Skill，已经覆盖 95% 写作发布流程：

Skill 作用
hexo_new_post 新建文章
hexo_update_post 修改已有文章（patch）
hexo_generate 本地生成静态站点
hexo_deploy 部署到 GitHub Pages

✅ 简单
✅ 安全
✅ 组合能力强

✅ 三、Hexo Skill 目录结构（直接可用）

在你现有工程里新增：

✅ 四、Skill 1：新建 Hexo 文章（hexo new）

skills/hexo/new_post/skill.json

{

“name”: “hexo_new_post”,

“description”: “Create a new Hexo post with standard front-matter”,

“input_schema”: {

“title”: “string”,

“slug”: “string”,

“category”: “string”,

“tags”: “array<string>”

},

“output_schema”: {

“path”: “string”

}

}

``

⚠️ Agent 不指定路径
⚠️ Agent 不操作 front-matter 细节

skills/hexo/new_post/service.py

import subprocess

from pathlib import Path

def hexo_new_post(title, slug, category, tags):

subprocess.run(

[“npx”, “hexo”, “new”, “post”, title],

check=True

)

posts_dir = Path(“source/_posts”)

files = sorted(posts_dir.glob(“*.md”), key=lambda f: f.stat().st_mtime)

post = files[-1]

content = post.read_text(encoding=”utf-8”)

front_matter = f”””—

title: {title}

date:

categories: {category}

tags: {tags}

“””

body = content.split(“—“, 2)[-1]

post.write_text(front_matter + body, encoding=”utf-8”)

return {“path”: str(post)}

✅ 把 Hexo CLI 细节完全封装掉
✅ Agent 只关心“我有一篇新文章了”

✅ 五、Skill 2：修改现有文章（patch 模式）

这是你之前 Markdown Skill 的 Hexo 特化版。

skills/hexo/update_post/skill.json

{

“name”: “hexo_update_post”,

“description”: “Apply a safe patch to an existing Hexo post”,

“input_schema”: {

“path”: “string”,

“diff”: “string”

},

“output_schema”: {

“result”: “SUCCESS | FAILED”

}

}

skills/hexo/update_post/service.py

import subprocess

import tempfile

from pathlib import Path

def hexo_update_post(path, diff):

file_path = Path(path)

if not file_path.exists():

return {“result”: “FAILED”}

with tempfile.NamedTemporaryFile(mode=”w”, delete=False) as f:

f.write(diff)

patch_file = f.name

try:

subprocess.run(

[“git”, “apply”, patch_file],

check=True

)

return {“result”: “SUCCESS”}

except subprocess.CalledProcessError:

return {“result”: “FAILED”}

✅ 防止“全文重写事故”
✅ 每次修改都可 diff / git rollback

✅ 八、Agent 现在是如何“理解 Hexo 发布流程”的？

Agent 认知层：

我要发布一篇文章

↓

是否已有文章？

↓

更新 or 新建

↓

可以发布了吗？

↓

generate → deploy

Agent 执行层：

hexo_new_post

→ hexo_update_post

→ hexo_generate

→ hexo_deploy

👉 Agent 永远没接触过：

  • Hexo CLI 参数
  • 目录结构
  • 配置文件
  • GitHub Pages 细节
