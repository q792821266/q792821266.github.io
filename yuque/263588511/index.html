很好，现在我们把 Hexo 写作 Prompt + 发布工作流 Prompt合并成一套「真正可用、耐用、可演进」的 Agent 行为规范。
这一步做完，你的 Agent 才算真正“懂你的博客、懂 Hexo、懂怎么稳妥地发文章”。

下面我会给你：

  1. ✅ **一份完整可直接使用的 **agent/prompt.md（Hexo 专用）
  2. ✅ 对应的“写作 → 编辑 → 发布”隐含工作流解释
  3. ✅ 使用示例（你该如何跟 Agent 对话）
  4. ✅ 后续你可以个性化的地方

✅ 一、Hexo 专用 Agent Prompt（完整版）

📁 文件路径建议：

你可以直接复制以下内容。

✅ agent/prompt.md

✅ 二、这份 Prompt 背后隐含的「完整 Hexo 工作流」

有了这份 prompt，你的 Agent 在**“脑子里默认就是这样工作的”**：

你：帮我整理这篇文章并发布

Agent 思维流程：

1️⃣ 这是 Hexo 博客文章

2️⃣ 我只能动 source/_posts

3️⃣ 我要先整理结构

4️⃣ 改动必须是 patch

5️⃣ 发布前必须确认

6️⃣ 发布就是：

→ hexo_generate

→ hexo_deploy

你不需要每次强调 Hexo，也不需要提醒它不要乱发，
这些边界已经被 prompt 固化了。

✅ 三、你以后可以这样和 Agent 对话（示例）

✅ 示例 1：只整理，不发布

帮我整理这篇文章的结构，只指出问题，不要直接改。

Agent 会：

  • 按结构给 review
  • 不会动文件
  • 不会碰 Hexo

✅ 示例 2：整理 + patch，但不发布

按你建议修改文章，但先不要发布。

Agent 会：

  • 生成 diff
  • 调用 hexo_update_post
  • 停在 commit 前

✅ 示例 3：完整写作流程（最常用）

帮我优化这篇文章，确认后直接发布。

Agent 会：

  1. review
  2. patch
  3. 等你确认
  4. hexo_generate
  5. hexo_deploy
