AWS SAA备考

  1. Amazon Macie 是一项专门用于发现敏感数据和保护数据安全的服务。Amazon Macie 可以运行数据发现作业，利用其托管的标识符和数据类型来发现包含敏感信息的数据，如个人可识别信息（PII）或财务信息，包括护照号码和信用卡号码。

  2. AWS CloudTrail可记录AWS账户的API活动，包括对资源的配置更改，主要用于审计AWS资源的操作历史。它会记录谁执行了哪些操作，因此可以用于跟踪资源更改的来源。

  3. Amazon GuardDuty用于检测安全威胁，而不是软件漏洞扫描和打补丁。启用Amazon RDS Protection功能可以通过Amazon GuardDuty来监视和识别数据库的异常活动，包括失败的登录尝试，而不需要过多的操作开销。

  4. Amazon Inspector和AWS Systems Manager Patch Manager是AWS的服务， 用于自动化安全评估，专门用于扫描EC2实例的软件漏洞并定期打补丁这些漏洞

  5. AWS Config用于评估和监视资源配置的符合性，它可以自动检查不合规的规则，通常用于评估和强制执行配置规则，提供了一个方便的方式来管理应用程序的配置。但在确认特定IAM用户的更改时，AWS CloudTrail是更常用的工具。而AWS Secrets Manager则提供了安全地存储和检索凭据的功能。

  6. 为了解决DynamoDB吞吐不足导致的可用性问题和用户请求丢失问题，使用Amazon SQS队列和Lambda来缓冲写入DynamoDB可以有效地平滑请求流，避免超出DynamoDB的吞吐限制。这样，即使DynamoDB暂时无法处理所有的写入请求，这些请求也不会丢失，而是被排队等待处理。DynamoDB Accelerator (DAX) 可以提高DynamoDB的性能，但不提供请求缓冲功能，也不适合解决吞吐不足的问题

  7. NAT网关是为了让私有子网中的EC2实例可以访问互联网；配置一个VPC终端节点，允许应用程序通过VPC内部的终端节点访问（S3存储桶），而不需要使用互联网连接

  8. AWS Systems Manager Session Manager允许您通过AWS Management Console、AWS CLI或AWS SDKs等方式连接到EC2实例，而无需共享SSH密钥。

  9. AWS Snowball Edge是一种物理设备，可以在本地加载数据，然后将设备返还给AWS，AWS会将数据导入到Amazon S3中。这种方法可以在不占用过多网络带宽的情况下快速迁移大量数据，尤其是对于大型视频文件。考虑到公司的网络带宽有限，使用AWS Snowball是最合适的解决方案

  10. CloudFront主要用于内容分发，不适用于TCP和UDP流量的路由

  11. 使用了AWS Global Accelerator，可以将请求路由到最近的边缘位置，从而实现低延迟，特别适用于具有低延迟和高可用性要求的应用程序。

  12. ALB可以用于路由流量到设备，然后将经过检查的流量传递给Web服务器。这种方式可确保在数据包到达Web服务器之前进行检查，以满足安全需求

  13. 网络负载均衡器不支持HTTP/HTTPS流量路由

  14. 中转网关通常用于连接不同的VPC

  15. 网关负载均衡器适用于传统网络流量负载均衡，而不是HTTP/HTTPS流量路由

  16. Amazon Athena是一种无服务器查询服务，允许您在Amazon S3上运行SQL查询，而无需将数据迁移到其他存储或进行复杂的ETL过程。这使得它成为处理存储在S3中的日志文件的理想选择，因为它可以在需要时执行简单查询，而不需要对现有架构进行大规模更改

  17. Amazon Redshift适用于数据仓库工作负载，它需要将数据加载到Redshift中，需要一定时间来加载和查询数据，不适合近实时查询需求。

  18. Amazon CloudWatch Logs适用于日志存储和监控，但不支持SQL查询

  19. Amazon Kinesis Data Analytics用于实时数据分析，不适合用于消息分发和解耦

  20. Amazon EventBridge是一个高度可扩展的事件总线服务，可以将事件传递给多个目标，包括Lambda函数。使用EventBridge可以将消息直接发送到目标Lambda函数，而无需中间层服务，因此可以减少操作开销。 EventBridge还可以轻松地实现消息过滤和路由，以确保目标Lambda函数只接收所需的消息。EventBridge (CloudWatch Events)这通常用于事件驱动的架构，不适合作业调度。

  21. AWS Secrets Manager： Secrets Manager 是一项 AWS 服务，用于安全地存储和管理敏感信息，如数据库凭据、API密钥和其他凭据。使用 Secrets Manager 可以更轻松地实现凭据的安全存储、轮换和访问。自动轮换可以定期更改凭据，增加安全性。

  22. AWS Systems Manager Parameter Store： Parameter Store 也是一项 AWS 服务，用于存储配置和凭据。然而，它通常用于存储非敏感的配置数据，而 Secrets Manager 更专注于安全地存储凭据。

  23. Amazon Detective用于分析安全事件，不直接用于软件漏洞扫描和打补丁。

  24. AWS Key Management Service(KMS)是AWS的密钥管理服务，可用于加密数据、保护密钥并确保数据的安全性。

  25. Amazon FSx for Windows File Server是托管的文件存储服务，可轻松集成到公司的Active Directory中，从而使员工可以安全地访问文件。

  26. 启用Amazon Elastic Block Store (Amazon EBS)快速快照恢复功能可以快速创建AMI。这可以提供最小的初始化延迟，以满足需求，而无需复杂的额外配置或操作。

  27. 使用AWS WAF (Web Application Firewall) 可以帮助防止SQL注入攻击。AWS WAF可用于过滤和阻止恶意SQL注入尝试，以增加应用程序的安全性。

  28. 使用Lake Formation可以非常方便地实施基于列级的访问控制，而不需要额外的IAM策略或存储桶策略。

  29. 使用Amazon Cognito进行身份验证可以提供适合少于100个用户的身份验证解决方案，并且无需费用（在一定用户数限制内）。可以与API Gateway集成以保护REST API。用户池是Cognito的一部分，它提供了对用户的身份验证和管理。使用Cognito用户池可以轻松实现对用户进行验证，并确保只有经过验证的用户可以访问API。

  30. Lambda@Edge进行授权可以在全球范围内提供授权

  31. Amazon S3文件网关是一种存储网关类型，专门用于将本地文件存储与Amazon S3云存储集成。它提供了一种将本地文件数据迁移到Amazon S3并与客户工作站保持相同外观和感觉的方式

  32. EC2实例性能储蓄计划（EC2 Instance Savings Plan）允许公司在接下来的3年内最大化成本节省，同时具有更大的灵活性，因为它允许在不同实例大小和系列之间变更，而不受限于特定的实例规格

  33. AWS Step Functions提供了构建和管理分布式应用程序的能力，特别适用于事件驱动架构。你可以使用Step Functions创建一个状态机，用于定义工作流的步骤和逻辑，并通过状态机来调用AWS Lambda函数执行这些步骤。这种方式结合了无服务器和事件驱动的概念，并且可以最小化运维开销。

  34. 启用RDS代理（RDS Proxy，选项B）是一种解决在高峰时段或不可预测流量时，减少数据库连接超时错误的有效方法。RDS代理可以帮助管理数据库连接池，减轻了数据库上的连接负载，从而减少了连接超时的风险，而无需对应用程序代码进行太多更改。

  35. Amazon Fargate 是可与 Amazon ECS 结合使用的技术，使您在运行容器时不必管理 Amazon EC2 实例的服务器或集群。使用 Amazon EventBridge 定时事件触发 Amazon ECS Fargate 任务，可以按需启动容器，而不必为底层的 EC2 实例支付固定的费用。

  36. Amazon API Gateway的接口端点是Amazon API Gateway与VPC之间的连接。接口端点允许您将API部署到VPC中，以便在通过互联网访问API时，流量将通过与VPC连接的端点传输。

  37. Amazon SQS FIFO队列是唯一一个可以保证事件按照特定顺序处理的选项

  38. 使用API使用计划和API密钥，是最直接且操作开销最小的方式来实现对没有订阅的用户访问的限制。您可以轻松配置API使用计划，将用户划分为有和没有订阅的用户，然后相应地限制其访问权限。这个方法也比较容易管理和维护。

  39. 安全组用于允许关联资源（例如 EC2 实例）的入站和出站流量。网络 ACL （access control list）用于允许或拒绝子网级别的入站和出站流量。在大多数情况下，使用安全组即可满足您的需求。不过，如需为 VPC 增加额外的安全保护，您可以使用网络 ACL。

  40. 服务控制策略（SCP）是AWS Organizations中的一种策略类型，可用于控制组织中的成员账户的权限和资源访问。您可以使用SCP来限制对标签的修改，只允许授权的主体执行

  41. Snowmobile主要用于迁移极其大规模的数据中心

  42. AWS Snowball Edge Compute Optimized设备通常用于计算密集型工作负载，不是用于数据库迁移的首选工具

  43. AWS Snowball Edge Storage Optimized设备，这是一种物理设备，用于快速迁移大量数据到AWS. AWS Database Migration Service（AWS DMS）和AWS Schema Conversion Tool（AWS SCT）可以协助数据库迁移和模式转换，使迁移更容易

  44. WS Control Tower 提供了一种按照规范性最佳实践设置和管理 AWS 多账户环境的简单方法。AWS Control Tower 协调了其他几项AWS 服务的能力 AWS Organizations，包括 AWS Service Catalog AWS IAM Identity Center。通过在组织管理账户中部署AWS Control Tower环境，并在环境中启用AWS Security Hub和AWS Control Tower账户工厂，您可以实现对所有现有或新的AWS账户中的所有API调用和登录进行审计。此外，AWS Control Tower还能够自动执行AWS基本安全最佳实践（FSBP）标准，并提供对AWS账户是否符合这些标准的可见性和报告。

  45. S3 Storage Lens是一项全新的Amazon S3功能，提供对存储桶活动的深入见解，并可以配置以满足不同的数据访问和管理需求。通过配置S3 Storage Lens，可以轻松地报告不完整的多部分上传对象的数量，而且操作开销相对较小。

  46. Amazon Neptune 是一种图形数据库服务，适用于存储用户档案、关系和互动数据。Neptune Streams 可以捕获 Neptune 数据库中的更改，并将其传递给应用程序，以便监视数据库中的任何更改。

  47. Trusted Advisor 借鉴了从为成千上万的 AWS 客户提供服务中学到的最佳实践。 Trusted Advisor 检查您的 AWS 环境，然后在有机会节省资金、提高系统可用性和性能或帮助填补安全漏洞时提出建议。

  48. AWS X-Ray 是一项服务，它收集有关您的应用程序所处理的请求的数据，并提供可用于查看、筛选和深入了解这些数据的工具，以识别问题和优化机会。

  49. AWS Outposts 提供了一个在本地扩展 AWS 服务的方式，因此您可以在本地进行数据处理，同时仍然能够享受 AWS 云的优势。

  50. Amazon FSx for NetApp ONTAP 提供了一个高性能的文件存储解决方案，支持多种操作系统，并且可以使用 SMB (Server Message Block,可以在局域网不同计算机之间进行文件、打印机等资源共享，和 NFS 功能类似。)和 NFS 协议进行访问。

  51. Transit Gateway 可以集中管理所有 VPC 之间的通信，并通过路由传播功能自动传播路由。

  52. AWS Identity and Access Management (IAM) 是一种 Web 服务，可以帮助您安全地控制对 AWS 资源的访问。借助 IAM，您可以集中管理控制用户可访问哪些 AWS 资源的权限。可以使用 IAM 来控制谁通过了身份验证（准许登录）并获得授权（具有z权限）来使用资源。IAM用户通常用于访问AWS资源，而不是用于Web服务的用户身份验证。

  53. 启用系统管理器中的默认主机配置管理是最简单且满足要求的解决方案。通过启用此功能，可以使 EC2 实例自动与 Systems Manager 进行集成，无需创建新的 IAM 角色或用户。默认情况下，此功能会为 EC2 实例自动创建必要的 IAM 角色，并确保应用程序的运行不会受到影响。

  54. VPC 对等连接是两个 VPC 之间的网络连接，通过此连接，您可以使用私有 IPv4 地址或 IPv6 地址在两个 VPC 之间路由流量。当您跨不同 AWS 区域在 VPC 之间建立对等关系时，不同 AWS 区域中的 VPC 中的资源（例如 EC2 实例和 Lambda 函数）可以使用私有 IP 地址相互通信，无需使用网关、VPN 连接或网络设备。这些流量保留在私有 IP 空间中。所有区域间流量均经过加密，没有单点故障或带宽瓶颈。流量一直处于全球AWS骨干网络中，不会经过公有 Internet，这样可以减少面临的威胁，例如常见攻击漏洞和 DDoS 攻击。

  55. 要将您的 VPC 相互连接，请参阅《Amazon VPC 对等连接指南》中的 VPC 对等连接配置。

  56. 要将 VPC 连接到您自己的网络，请参阅《AWS Site-to-Site VPN 用户指南》中的** **Site-to-Site VPN 架构。

  57. 要将您的 VPC 相互连接并连接到您自己的网络，请参阅《Amazon VPC 中转网关》中的 中转网关示例。

  58. 使用Amazon Kinesis Data Streams能够处理大量流量，并且保证按照接收顺序处理更新。

  59. S3传输加速通过优化数据传输路径来加速上传到Amazon S3的速度，从而降低了上传内容的延迟。与CloudFront不同，S3传输加速专门用于加速与S3的上传，这对于本地新闻应用的用户体验优化是更好的选择。

  60. S3 \ EBS \EFS 如何选择 （ref: 何时选择 Amazon EFS）
    Amazon EFS 提供共享文件存储，供 AWS 云和本地服务器中的计算实例使用。需要共享文件访问的应用程序可以使用 Amazon EFS 进行可靠的文件存储，同时为数千个客户端提供高聚合吞吐量。Amazon EBS 是一种云块存储服务，提供从单个 Amazon EC2 实例到专用存储卷的直接访问。需要对单个主机进行持久专用块访问的应用程序可以使用 Amazon EBS 作为高可用、低延迟的块存储解决方案。Amazon EFS 通过 NFSv4 协议使用传统文件共享权限模型和分层目录结构提供对数据的共享访问。使用操作系统提供的标准文件系统接口访问数据的应用程序可以使用 Amazon EFS 来利用云中文件存储的可扩展性和可靠性，而无需编写任何新代码或调整应用程序。Amazon S3 是一个对象存储平台，使用简单的 API 来存储和访问数据。不需要文件系统结构且旨在与对象存储配合使用的应用程序可以使用 Amazon S3 作为大规模可扩展、持久、低成本的对象存储解决方案。

  61. 在AWS中，回收站（或称为“回收站”）是一种用于存储删除的资源的临时存储区域。当删除资源时，它们将被移动到回收站中，并在一定时间后永久删除。通过创建保留规则，可以确保在删除后一段时间内保留 AMI，从而提供了一种快速和有效地恢复意外删除的 AMI 的解决方案。这种方法的运维开销最小，因为它不涉及额外的存储、复制或管理任务。

  62. AWS Systems Manager Session Manager 提供了一种安全且受管的方法来远程连接到 EC2 实例，而不需要暴露 SSH 端口或设置 VPN 连接。

  63. AWS Direct Connect 通过标准的以太网光纤电缆将您的内部网络链接到某个 AWS Direct Connect 位置。通过此连接，您可以绕过网络路径中的互联网服务提供商，直接创建通往公共 AWS 服务（例如 Amazon S3）或 Amazon VPC 的虚拟接口。

  64. 使用 AWS SCT （AWS Schema Conversion Tool ）可以将 Oracle 数据库的模式转换为 Aurora PostgreSQL 兼容的模式，而 AWS DMS 则可用于迁移现有数据并在迁移过程中复制正在发生的更改。

  65. Amazon QLDB (Amazon Quantum Ledger Database)是一种托管的区块链式分类账数据库，提供了不可变的、经过加密的、可验证的数据更改日志。它可以有效地满足要求，并且不需要额外的运维支持。Amazon Quantum Ledger Database（Amazon QLDB）是一个完全托管的分类账数据库，提供了一个透明、不可变、可通过加密方式验证的事务日志，且该事务日志由一家可信的中央机构拥有。您可以使用 Amazon QLDB 来跟踪所有应用程序数据更改，并不断维护完整且可验证的更改历史记录。

  66. AWS系统管理器主要用于管理AWS资源，而不是本地服务器

  67. AWS Security Hub 为您提供了 AWS 中安全状态的全面视图，可帮助您评测您的 AWS 环境是否符合安全行业标准和最佳实践。Security Hub 可跨 AWS 账户、AWS 服务、和受支持的第三方产品收集安全数据，并可帮助您分析安全趋势，以及确定最高优先级的安全问题。

  68. 通过在公司的数据中心安装AWS Outposts机架，可以在本地运行AWS托管服务，包括Amazon EKS，而不会将数据存储在任何远程站点或云中。

  69. 使用Amazon Elastic Container Registry (Amazon ECR)的基本扫描功能可以在每次推送新镜像时自动对镜像进行扫描，而无需对工作负载进行任何修改。

  70. AWS PrivateLink 是一种高度可用、可扩展的技术，您可以使用它以私密方式将您的 VPC 连接到服务，就像这些服务位于您的 VPC 中一样。您无需使用互联网网关、NAT 设备、公有 IP 地址、 AWS Direct Connect 连接或 AWS Site-to-Site VPN 连接即可允许从您的私有子网与服务进行通信。

  71. AWS Glue 是一项无服务器数据集成服务，可让使用分析功能的用户轻松发现、准备、移动和集成来自多个来源的数据。您可以将其用于分析、机器学习和应用程序开发。它还包括用于编写、运行任务和实施业务工作流程的额外生产力和数据操作工具。通过使用 AWS Glue，您可以发现并连接到 70 多个不同的数据来源，并在集中式数据目录中管理您的数据。您可以直观地创建、运行和监控“提取、转换、加载（ETL）”管道，以将数据加载到数据湖中

  72. AWS Glue DataBrew 是一种可视化数据准备工具，让用户无需编写任何代码即可清理数据并实现标准化。与定制开发的数据准备相比，使用 DataBrew 可将准备用于分析和机器学习 (ML) 的数据所需的时间缩短多达 80%。您可以从 250 多种现成的转换功能中进行选择，以自动执行数据准备任务，例如筛选异常、将数据转换为标准格式以及更正无效值。通过使用 DataBrew，业务分析师、数据科学家和数据工程师可以更轻松地进行协作，从原始数据中获取见解。由于 DataBrew 是无服务器的，因此无论您的技术水平如何，您都可以浏览和转换数 TB 的原始数据，而无需创建集群或管理任何基础架构。AWS Glue DataBrew是一种用于数据准备和数据清洗的托管服务，可以方便地处理营销数据。是一个完全托管的数据准备服务，提供了可视化的界面和预构建的转换功能，不需要编写代码。

  73. AWS Transfer Family为使用SFTP协议的供应商提供了一个托管的服务，他们可以继续使用他们熟悉的SFTP应用程序上传数据，而不需要更改他们的工作流程或学习新的API。

  74. AWS Transfer Family 是一种安全的传输服务，使您能够将文件传入和传出 AWS 存储服务。Transfer Family 是该 AWS Cloud 平台的一部分。 AWS Transfer Family 为通过 SFTP、AS2、FTPS 和 FTP 将文件直接传入和传出亚马逊 S3 或 Amazon EFS 提供完全托管的支持。

  75. Amazon Comprehend是一项用于自然语言处理的托管服务，可用于分析文本内容和情感。通过将提取的见解提供给Amazon Comprehend进行分析，可以轻松地获得关于新闻报道内容和情感的见解，而且操作开销较小。QuickSight适用于已经分析过的数据，倾向于展示，而不是进行文本分析。

  81. ALB、NLB 和 GLB 在网络通信的不同层面运行。ALB 在 OSI 第 7 层上运行，允许应用程序级流量操作和路由。NLB 在第 4 层运行，用于基于端口和 IP 地址的网络级流量管理。GLB 在第 3 层和第 7 层运行，在网络层面提供均衡和路由服务以及网关功能。

  82. 使用场景：

  83. 当您需要灵活的应用程序级流量管理和路由时，ALB 是一个不错的选择。这是微服务、容器化环境和 Web 应用程序的理想之选。它的功能（例如 SSL 终止、会话保持和基于内容的路由）使其能够为复杂的路由场景提供帮助。

  84. NLB 最适合实现高性能、低延迟和可扩展的网络级均衡。在传输层分配流量的应用程序使用 NLB，尤其是考虑到其可靠性。游戏系统、媒体流式传输服务和主要 IoT 系统都使用 NLB。

  85. 当您在网络网关级别上进行均衡时，GLB 是理想的选择。例如，如果您管理云和本地环境之间或跨不同区域的流量，GLB 就能很好地发挥作用。由于它结合了 OSI 第 3 层和第 4 层均衡功能，因此可以在不同的区域和网络之间路由流量。由于它支持基于 IP 的路由，它可以在虚拟网关之间分配流量，因此可以提供高可扩展性和可用性。

  86. 差异摘要：ALB 与NLB 与GLB

应用程序负载均衡器（ALB） 网络负载均衡器（NLB） 网关负载均衡器（GLB）
OSI 层 适用于第 7 层，即应用层。 适用于第 4 层，即传输层。 适用于网络层、第 3 层和第 7 层。
目标类型 适用于 IP、实例和 Lambda 目标类型。 适用于 IP、实例和 ALB 目标类型。 适用于 IP 和实例目标类型。
代理行为 结束连接。 结束连接。 不会终止流程。
协议 支持 HTTP、HTTPS 和 gRPC 协议。 支持 TCP、UDP 和 TLS 协议。 支持基于 IP 的路由。
算法 循环法。 哈希流。 路由表查询。

  4. 客户托管式密钥您创建的 KMS 密钥是客户托管式密钥。客户托管密钥是在您的 AWS 账户 中创建、拥有和管理的 KMS 密钥。您可以完全控制这些 KMS 密钥，包括建立和维护其密钥策略、IAM policy 和授权、启用和禁用它们、轮换其加密材料、添加标签、创建别名（引用了 KMS 密钥）以及计划删除 KMS 密钥。
    AWS 托管式密钥 是由与 AWS KMS 集成的 AWS 服务代表您在账户中创建、管理和使用的 KMS 密钥。通常，除非您需要控制保护资源的加密密钥，否则 AWS 托管式密钥是不错的选择。您不必创建或维护密钥或密钥策略。您有权查看账户中的 AWS 托管式密钥、查看其密钥策略以及在 AWS CloudTrail 日志中审核其使用情况。但是，您无法更改 AWS 托管式密钥的任何属性、对它们进行轮换、更改其密钥策略或安排删除它们。
    AWS 拥有的密钥** **是 AWS 服务拥有并管理以用于多个 AWS 账户 中的 KMS 密钥的集合。虽然 AWS 拥有的密钥 不在您的 AWS 账户 中，但 AWS 服务可以使用 AWS 拥有的密钥 来保护您账户中的资源。通常，除非您需要审核或控制保护资源的加密密钥，否则 AWS 拥有的密钥是不错的选择。AWS 拥有的密钥完全免费（没有月度费用或使用费用），它们不计入您账户的 AWS KMS 配额，而且简单易用。您不必创建或维护该密钥或其密钥策略。

安全组 网络 ACL
在实例级别运行 在子网级别运行
仅支持允许规则 支持允许规则和拒绝规则
有状态：返回数据流会被自动允许，不受任何规则的影响 无状态：返回数据流必须被规则明确允许
会在决定是否允许数据流前评估所有规则 在决定是否允许流量时，按顺序处理规则，从编号最低的规则开始
只有在启动实例的同时指定安全组、或稍后将安全组与实例关联的情况下，操作才会被应用到实例 自动应用于与之关联的子网中的所有实例（因此，如果安全组规则过于宽松，它提供额外的防御层）
