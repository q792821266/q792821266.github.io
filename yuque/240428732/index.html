数据库中的log

Redo Log （重做日志）

  • 作用：用于恢复已提交事务的数据，保证事务的持久性（Durability）。

  • 工作机制：

  • 在事务提交前，先将修改记录写入 redo log。

  • 如果数据库崩溃，重启时可以通过 redo log 将已提交但尚未写入磁盘的数据“重做”。

  • 特点：

  • 是 物理日志，记录的是数据页的修改。

  • 通常是 顺序写入，性能高。

  • 应用场景：MySQL 的 InnoDB 引擎使用 redo log 来实现 WAL（Write-Ahead Logging）机制。

Undo Log （回滚日志）

  • 作用：用于回滚未提交事务，保证事务的原子性（Atomicity）。

  • 工作机制：

  • 在修改数据前，先记录原始数据到 undo log。

  • 如果事务失败或被回滚，可以通过 undo log 恢复到原始状态。

  • 特点：

  • 是 逻辑日志，记录的是数据的反向操作。

  • 也用于 MVCC（多版本并发控制）实现快照读。

  • 应用场景：InnoDB 使用 undo log 来支持事务回滚和 MVCC。

Bin Log （Binary Log，二进制日志）

  • 作用：用于记录所有修改数据库的 SQL 语句，支持数据恢复、主从复制等。

  • 工作机制：

  • 记录的是 SQL 层的操作（如 INSERT, UPDATE, DELETE）。

  • 是 逻辑日志，与存储引擎无关。

  • 特点：

  • 只记录已提交事务。

  • 可以用于数据恢复（通过重放 binlog）和主从同步。

  • 应用场景：MySQL 的主从复制、数据恢复、审计等。
