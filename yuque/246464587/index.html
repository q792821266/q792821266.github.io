HTTP

发展过程

HTTP/1.0

  • 设计初衷：HTTP/1.0的设计初衷是为了简单的网页传输，典型场景是请求一个HTML网页，服务器返回后就关闭连接。

  • 无状态协议：这时候的HTTP是无状态的，每次请求独立，服务器不需要记住客户端状态

  • 连接策略：默认是短连接，即每次请求完成后立刻关闭TCP连接

  • 优点：实现简单，资源释放快

  • 缺点：每次请求都要重新建立TCP（三次握手），性能差

HTTP/1.1

  • 性能问题暴露：随着网页越来越复杂，一个网页可能包含几十个资源（CSS 、JS、图片），频繁建立连接开销大
  • 解决方案：引入Connection：keep-alive， 允许复用TCP连接。但仍然是串行请求，一个连接上只能处理一个请求，后续的请求必须等待前一个完成（队头阻塞）

HTTP/2

  • HTTP/1.1的问题

  • 队头阻塞（Head-of-Line Blocking）

  • 浏览器通常会开多个TCP连接（6-8个）来并发请求，增加服务器压力

  • HTTP/2的改进

  • 单连接多路复用：一个TCP连接可以并发多个请求，避免队头阻塞

  • 二进制分帧：更高效的传输

  • 头部压缩：减少冗余

  • 结果：HTTP/2的长连接不仅仅是“保持连接”，而是充分利用连接，性能提升显著

总结对比

协议版本 默认连接策略 特点
HTTP/1.0 短连接 每次请求都重新建立 TCP
HTTP/1.1 长连接（Keep-Alive） 连接复用，但串行请求
HTTP/2 长连接 + 多路复用 一个连接并发多个请求

HTTP/2 实现高效长连接是因为引入了多路复用，彻底解决了 HTTP/1.1 的性能瓶颈。

为什么一条TCP连接能支持并发

  • TCP是字节流协议，它保证数据的顺序和可靠传输，不关心应用层的“消息边界”

  • 在HTTP/1.1中，虽然可以复用连接，但请求必须串行，因为协议没有表示哪个响应对应哪个请求

  • HTTP/2引入了帧（Frame）+ 流（Stream）概念

  • 每个请求/响应被拆分成多个帧

  • 每个帧带有Stream ID ，标识属于哪个请求

  • TCP仍是一条连接，但应用层通过Stream ID区分不同请求，实现并发

多路复用

多路复用的关键点是：在一条TCP连接上并发处理多个HTTP请求和响应，从而提高连接利用率，减少延迟和资源消耗。

为什么叫多路复用

路（Channel），在网络术语中通常指的是逻辑通道

在HTTP/2中，虽然底层只有一条TCP连接，但是应用层通过Stream ID把这条连接虚拟划分成了多个独立的逻辑通道，每个通道对应一个请求/响应流

所以多路指的是，多条逻辑通道(Channel)

复用指的是复用底层的TCP连接

**通过在应用层创建多条逻辑通道（Stream/Channel），复用一条底层 TCP 连接，从而提高连接利用率和并发能力。 **

工作原理

  • 单 TCP 连接 → 多个逻辑流（Stream）。

  • 每个流可以独立发送请求和响应，互不阻塞。

  • 例如：

  • 请求 A、请求 B、请求 C 可以同时发送。

  • 响应也可以交错返回，客户端根据 Stream ID 组装。
