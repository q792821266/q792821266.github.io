10. 用久了会遇到：续期、退出与离职停用

10.1 为什么退出 OA 后，又自动登录回来

OA 会话没了，但中心会话仍然有效。再次访问 OA，浏览器被送到中心，中心又无交互地确认身份。

这正是多份会话分别管理的结果。产品必须定义“退出本应用”还是“退出统一账号”。

动作 直接处理的状态 不一定自动发生的事情
退出 OA OA 本地会话 CRM 和中心会话退出
退出认证中心 中心会话 OA、CRM 的已有本地会话失效
全局退出 按支持的协议通知关联应用 所有 API 令牌瞬间失效
撤销刷新令牌 该凭证不能继续续期 所有已发 JWT Access Token 立即失效
停用员工账号 后续认证与授权受到限制 已有会话、API Key、后台任务自动全部停止

退出应让服务端会话失效，再清理 Cookie。只删浏览器 Cookie，不能保证被盗的旧会话标识失效。

10.2 如何让多个应用一起退出

身份平台和应用可以使用支持的单点退出协议。以 OIDC 后通道退出为例，平台直接通知应用，应用验证 Logout Token⁷³，找到关联本地会话并使其失效。它不能当作登录结果或 API 访问令牌使用。R5

需要保存中心会话与本地会话的映射，并处理通知重试、重复通知与应用不可达。后通道是服务端之间通信，前通道依赖浏览器；二者的故障方式不同。

全局退出不是一个无条件原子操作。应说明可接受的失效时间与失败兜底，而不是承诺网络中任何应用都瞬时同步。

10.3 Access Token 过期后怎么办

对于需要持续访问 API 的应用，平台可以按策略签发 Refresh Token⁷⁴。应用将它交给 Token 端点，申请新的 Access Token。

Refresh Token 是否签发、可以使用多久、是否需要重新认证，取决于授权与策略。它本身也是高价值凭证，应受保护地保存。

如果平台采用刷新令牌轮换，一次刷新会得到新 Refresh Token。多个请求同时使用旧令牌，可能触发复用检测并使相关授权失效。后端应按会话协调刷新，避免并发重复使用，并原子更新存储。

10.4 离职账号怎样在约定时间内停止访问

统一目录停用账号只完成了一步。还需要考虑已有应用会话、已发 Access Token、长期凭据和后台任务。

可以组合会话撤销、停用事件通知、关键接口查最新状态、令牌短有效期和有边界的缓存。先明确“多久内不能访问哪些资源”，再选机制。

如果只在首次 SSO 登录时创建本地账号，这叫 JIT⁷⁵ 开通。它不能单独保证离职停用及时传播。SCIM⁷⁶ 可以用于用户和组的创建、更新与停用同步，处理生命周期管理，不负责浏览器登录。R9

11. 按流程找风险与故障

11.1 从哪个步骤看安全问题

流程位置 容易出现什么问题 应对方向
输入密码 撞库、钓鱼、账号枚举 HTTPS、适当限速、风险控制、MFA 或通行密钥
保存密码 明文、可逆加密、只用快速散列 使用适当参数的密码散列算法，如 Argon2id⁷⁷，并配独立随机盐
发起登录 回跳 URL 被用来跳到攻击网站 精确回调注册、受控站内回跳、可靠事务绑定
接收回调 登录 CSRF、授权码注入、回放 state/nonce/PKCE 等正确的协议保护，一次性事务
验证声明 只解码、不验签；忽略 iss/aud；SAML 消费未验证元素 成熟库、可信配置、完整协议检查
创建会话 登录后沿用攻击者预置的标识 登录和权限提升时更换会话标识
持续使用 XSS⁷⁸ 盗令牌、CSRF 借 Cookie 操作 防 XSS、合理保管令牌、CSRF 防护、安全 Cookie
调 API scope 足够就放行，未检查用户和资源关系 角色、租户与资源归属校验
续期 刷新令牌泄露、并发轮换冲突 后端保护、轮换、串行刷新与重放检测
退出 只清本地状态、通知丢失 定义退出范围、幂等⁷⁹通知、重试和过期兜底

MFA 是增加认证因素，例如密码加持有的安全设备；两个密码不构成两个不同因素。通行密钥可通过 WebAuthn⁸⁰ 公钥凭据完成挑战签名，服务端验证公钥证明和站点绑定，不需要接收用户指纹。R8

MFA 或通行密钥加强的是认证，不能代替后续会话保护和业务授权。

11.2 为什么“JWT 放 localStorage 就完成登录”不完整

localStorage⁸¹ 能被同源脚本读取，XSS 可能直接窃走其中的令牌。服务端 Web 应用可采用后端持令牌、浏览器持 HttpOnly 会话 Cookie 的方案，也就是常说的 BFF⁸² 模式。

HttpOnly 限制直接读 Cookie，但恶意脚本仍可能借当前会话执行操作。Cookie 会自动携带，又需要 CSRF 防护。因此存储位置的选择不会消除所有风险。

Bearer Token⁸³ 通常表示“拿到即可使用”，签名并不自动证明当前发送者就是最初接收者。高风险 API 可以评估 DPoP⁸⁴ 或 mTLS⁸⁵ 等发送方约束机制，同时继续执行权限检查。

state 不匹配 临时事务是否过期、跨标签页被覆盖、浏览器关联 Cookie 丢失、环境是否配错

排查时沿“浏览器跳转 → 临时登录事务 → 后端换码 → 结果验证 → 本地会话 → API 授权”逐段定位。

日志记录关联 ID、客户端、错误阶段与原因码。不要记录密码、完整令牌、会话 Cookie 或 SAML 响应，也不要把真实凭证提交到公开解码网站。

11.4 认证中心不可用会怎样

新登录通常受影响；已有 OA 会话是否可继续使用，取决于 OA 是否依赖中心实时查询。离线验证仍有效 JWT 的 API 也可能继续服务。

设计时要考虑平台和会话存储高可用、超时、公钥缓存与轮换。未知 kid 刷新必须受控，防止任意伪造令牌触发无界请求。旧公钥应按仍有效令牌与安全策略保留适当重叠窗口。

不能用“中心故障时接受未验证令牌”来降级。备用访问方案需要事先设计和审计。

12. 回头把容易混淆的名字放回原位

12.1 角色名称不等于服务器数量

看到的名字 它在强调什么 本文对应对象
认证中心、认证服务 集中验证身份与复用登录状态，属于架构表达 统一身份平台的认证功能
IdP 身份提供者，SAML 等场景常用 统一身份平台
Authorization Server OAuth 中处理授权与令牌签发的角色 平台的 OAuth 功能，可与认证合并部署
OP OIDC 的身份提供者角色 支持 OIDC 的同一平台
SP SAML 中消费身份结果并提供服务的角色 OA、CRM
RP OIDC 中依赖认证结果的应用 使用 OIDC 登录的 OA、CRM
OAuth Client 申请访问授权的应用 第三方日程助手；用 OIDC 登录的 OA 也可以是客户端
Resource Server 提供受保护资源的服务 OA 日程 API

同一个 OA 可以既是 OIDC Client，又对外提供日程 API、成为 Resource Server。角色取决于正在讨论哪一次交互。

有的文章宽泛地把身份平台都叫“认证授权中心”。阅读时应追问它此刻在做什么，而不是单凭名字判断是否另有一套系统。

12.2 协议、格式和浏览器机制分层看

层次 例子 本文中的用途
用户认证方式 密码、OTP⁸⁸ 一次性验证码、WebAuthn 公钥凭据认证 小林怎样向平台证明身份
跨系统认证与联合协议 SAML、OIDC；CAS 也可做集中登录 OA 怎样获得可信认证结果
委托授权框架 OAuth 2.0 日程助手怎样获得受限 API 访问能力
声明或凭证表示 SAML Assertion、JWT、随机不透明令牌 结果或凭证怎样表达与验证
浏览器状态机制 Cookie 浏览器怎样向对应站点携带状态标识
应用持续状态 Session OA 怎样延续登录与撤销本地访问

LDAP 是目录访问协议；Active Directory 是涉及多种协议的目录服务产品体系。Kerberos 适合某些域和内网认证场景，可以通过身份平台桥接到 Web 登录协议。

12.3 选型时怎么应用这些知识

  • 单应用：成熟框架的密码或通行密钥认证，加安全 Session，可能已经足够。
  • 企业多应用：统一身份平台加 OIDC 或 SAML；已有 CAS 环境可按既有能力接入。
  • 第三方访问用户资源：OAuth 委托授权；需要标准身份认证时结合 OIDC。
  • 服务调用服务：工作负载身份或 Client Credentials⁵¹ 等。后者代表应用身份，不涉及交互式用户登录，不能当作小林已经登录的证明。
  • 纯 SPA、原生 App：通常使用授权码加 PKCE，不能靠内置 secret 保密；原生 App 优先使用系统浏览器和受控回调。
  • 多租户 SaaS⁸⁹：按受控租户配置选择可信 issuer、回调和身份映射，不靠请求中的邮箱后缀单独认定成员资格。

企业客户采用 SAML，并不意味着必须先换掉它才能支持现代 API。身份平台可以桥接不同协议，应用按各自场景使用不同能力。

12.4 学完中间凭证后，再看 CAS 的票据式 SSO

CAS²⁶ 是另一种常见的集中登录协议。到这里已经理解“先传一张凭证，再由后端向中心取得后续结果”的交互，就可以回头看它的票据式 SSO。

CAS Server 是认证中心，CAS Client 是接入中心的业务应用。其服务票据 Service Ticket，简称 ST²⁹，用于让业务应用后端向中心验票，取得用户认证信息。

ST 只对特定服务有效，校验尝试会消耗它。不能拿 ST 当作访问 OA 日程 API 的长期令牌。service 地址不匹配、票据过期或重复消费是常见接入问题。R6

这种交互在形态上包含中间凭证，但 CAS ST 与 OAuth 授权码属于不同协议，兑换目的和验证规则不同，不能把一个协议的保护条件直接套到另一个上。

将 CAS 放到这里是教学顺序的选择。它说明基础 SSO 也可以采用票据式方案，不表示 CAS 必须先有 OAuth，也不表示所有 SSO 都必须先发一张中间票据。

13. 面试复习：用“问题—方案—代价”回答

13.1 两分钟讲完主线

最开始只有一个 OA，由 OA 自己校验密码并创建 Session。认证用来确认用户是谁，业务权限检查决定他能做什么。

增加 CRM 后，先通过统一目录解决账号重复管理，但两个系统还是分别登录。为复用认证，我们把登录职责放到统一认证中心。各应用跳转到中心获取可信结果，再建立自己的本地会话。跨域 SSO 依靠协议交互，不要求共享 Cookie。

接入更多系统后，用 CAS、SAML 或 OIDC 等标准减少自定义协议。第三方日程助手需要读取 OA 数据时，出现的是委托授权问题，可以用 OAuth 2.0 签发受限的 Access Token。已有身份平台也能承担授权服务器角色，不必另建一个中心。

Access Token 可以是不透明字符串，也可以使用 JWT。JWT 便于本地校验，但及时撤销需要额外机制。OIDC 则在 OAuth 上增加标准化身份认证，ID Token 给应用确认认证结果，Access Token 给 API 使用。

最后分别设计中心会话、本地会话和令牌的过期与撤销，补上 CSRF、XSS、资源权限、租户隔离、密钥轮换与高可用。

13.3 画系统设计图的顺序

  1. 先画用户、浏览器和两个业务系统，说明为什么需要统一登录。
  2. 再画统一身份平台与用户目录，明确不是每个角色名都要独立部署。
  3. 画出首次登录和第二个应用访问流程，标出三份会话。
  4. 如果题目涉及 API 委托，再增加客户端、令牌和资源服务交互。
  5. 说明会话/令牌生命周期、权限与租户校验、故障范围和容量取舍。

不要为了展示术语，在题目没有相应需求时直接画一大组中心。

13.4 建议动手验证的四个实验

¹ OA，Office Automation，办公自动化。本文指内部办公系统，常用于请假、报销、审批、公告和日程。

² CRM，Customer Relationship Management，客户关系管理。本文指记录客户资料、联系记录、销售跟进和商机的系统，例如记录某位客户的需求与下次跟进时间。

²⁶ CAS：Central Authentication Service，集中认证服务。常用票据和后端验票完成 SSO。

²⁹ ST：Service Ticket，服务票据。CAS 中面向特定服务的短期凭证。

⁵¹ Client Credentials，客户端凭据流程。应用用自己的身份获取访问令牌，不涉及交互式用户登录。

⁷³ Logout Token 是经过协议验证的退出通知令牌，用于通知应用结束关联会话，不能当作 ID Token 或 API 访问令牌。

⁷⁴ Refresh Token：刷新令牌。向平台申请新的访问令牌。

⁷⁵ JIT：Just-In-Time，即时开通。首次登录时创建本地账号。

⁷⁶ SCIM：System for Cross-domain Identity Management。同步用户、组及其生命周期。

⁷⁷ 密码存储中的盐是每个密码独立使用的随机数据，避免相同密码生成相同散列。Argon2id 是适合密码存储的一种散列算法。

⁷⁸ XSS：Cross-Site Scripting，跨站脚本攻击。防止恶意脚本在站点上下文中执行。

⁷⁹ 幂等：同一操作重复执行仍达到预期的同一效果。例如重复退出通知不会恢复会话或造成错误状态。

⁸⁰ WebAuthn：Web Authentication，Web 公钥凭据认证标准。通过挑战签名与站点绑定完成认证。

⁸¹ localStorage 是浏览器的本地键值存储，通常在关闭页面后仍保留，可被同源 JavaScript 读取。

⁸² BFF，Backend for Frontend，服务前端的专用后端。后端保存令牌，替前端调用接口。

⁸³ Bearer Token：持有者令牌。通常持有即可使用，要防泄露与重放。

⁸⁴ DPoP：Demonstrating Proof of Possession。用请求级密钥证明约束令牌发送方。

⁸⁵ mTLS：mutual TLS，双向 TLS。连接双方按配置进行证书认证。

⁸⁶ 域名是网站地址中的主机名称，例如 oa.example.net。本文的跨域指应用位于不同域名。

⁸⁷ kid：key ID，密钥标识。帮助从可信密钥集合中选择验签密钥。

⁸⁸ OTP：One-Time Password，一次性口令。例如认证器生成的短期验证码。

⁸⁹ SaaS：软件即服务。供应商托管软件，客户通过网络使用。
